# Тестирование

## Текущее автоматизированное покрытие

В проекте уже есть unit-тесты для части утилит и notification-логики:

- `common_ui/src/test/.../FormatTimeTest`
- `app/src/test/.../NotificationMessagesTest`
- `app/src/test/.../NotificationToggleLogicTest`

Также есть Android test stubs для app и database модулей.

## Рекомендуемые локальные проверки

```bash
./gradlew test
./gradlew :app:test
./gradlew :common_ui:test
./gradlew assembleGoogleDebug
```

## Ручной чеклист

### Управление тестами и вопросами

- создать тест
- переименовать тест
- добавить вопросы и варианты ответа
- проверить валидацию минимального и максимального числа ответов
- удалить вопрос и убедиться, что связанные записи очищаются

### Flow прохождения

- пройти сессию в `Exam`
- пройти сессию в `Workout`
- проверить сценарий с таймером
- проверить перемешивание вопросов и ответов
- проверить корректность итогового результата

### Ошибки и избранное

- ответить неправильно и убедиться, что вопрос попадает в flow ошибок
- добавить вопросы в избранное и проверить отдельный flow

### Импорт и хранение

- импортировать валидный JSON-файл
- импортировать невалидный JSON и убедиться в безопасной обработке ошибки
- перезапустить приложение и убедиться, что тесты сохраняются

### UI-проверки

- проверить светлую и темную темы
- проверить небольшие экраны
- проверить длинные названия тестов, вопросов и ответов

### Уведомления

- включить reminders
- смоделировать неактивность
- открыть приложение из notification destination
